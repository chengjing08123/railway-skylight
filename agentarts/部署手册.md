## 三、构建与部署（**不要用 `agentarts launch` 构建**）

### 为什么不用 launch 构建

`launch` 用经典 `docker build` 构建，产出的镜像索引标成 **linux/amd64**，
而运行时是 arm64 → 拉取时报 `no match for platform in manifest`。

`Dockerfile` 里那句 `FROM --platform=linux/arm64` **只影响拉基础镜像，不影响产物标记**。

### 正确做法：buildx 手动构建推送，再让 launch 只创建运行时

```powershell
$docker = "C:\Program Files\Docker\Docker\resources\bin\docker.exe"
cd "C:\Users\21264\ds harness work\work\contest-entry\agentarts"

# 1. 用 buildx 构建 arm64 并直接推送（--provenance=false 去掉多余的 attestation 层）
& $docker buildx build --platform linux/arm64 --provenance=false --sbom=false `
    -t "swr.cn-southwest-2.myhuaweicloud.com/skylight/skylight-check:latest" --push .

# 2. 确认远端 manifest 是单架构 arm64（不是 index）
& $docker buildx imagetools inspect "swr.cn-southwest-2.myhuaweicloud.com/skylight/skylight-check:latest"
# 期望：MediaType: application/vnd.oci.image.manifest.v1+json（不是 ...index...）

# 3. 确认 .agentarts_config.yaml 里 artifact_source.url 已指向该镜像，
#    这样 launch 会跳过构建、只在云端创建运行时
agentarts launch
```

> 改了代码要重新部署时：先 buildx 推送新镜像 → `agentarts destroy -y` → 等约 60 秒 →
> `agentarts launch`。**必须 destroy 再建**，否则云端会沿用旧的 Error 状态和缓存的失败结果
> （表现为报错里的 request_id 一直不变）。

## 四、调用

PowerShell 直接把 JSON 传给 `agentarts.exe` 会丢引号（报 `Payload must be valid JSON`），
用 Python 脚本传 argv：

```powershell
python invoke_agent.py                # CHECK，2 条作业的最小用例
python invoke_agent.py full           # CHECK，9/23 全部 12 条
python invoke_agent.py orchestrate    # 只编排（两套方案 + 代价）
python invoke_agent.py check-plan     # 只核查（方案 A）
python invoke_agent.py arbitrate      # 只仲裁（自己先编两套）
python invoke_agent.py negotiate      # 全链路：编排 + 核查 + 仲裁 + 留痕
```

### 四个 mode 的契约（省略即 CHECK，旧调用不用改）

| mode | 作用 | 关键入参 | 关键出参 |
|---|---|---|---|
| `CHECK` | 四节点核查（默认） | `window` `tasks` | `response` `conflictCount` `clauseRefs` |
| `ORCHESTRATE` | 只编排 | `window` `tasks` | `plans[]`（每套带 `cost`） |
| `CHECK_PLAN` | 只核查单个方案 | `plan`（或 `plans[0]`） | `conflictCount` `severe` `conflicts[]` |
| `ARBITRATE` | 只仲裁 | `plans[]` 或 `tasks` | `verdict{recommended,reason,fallback}` |
| `NEGOTIATE` | 全链路 | `window` `tasks` | 以上全部 + `trace` |

`NEGOTIATE` 的返回示例：

```json
{
  "mode": "NEGOTIATE", "status": "ok", "sessionId": "S-01b938ba3de8",
  "conflictCount": 0,
  "verdict": {"recommended": "A", "requiresHumanChoice": true,
              "fallback": "若方案 A 的代价不可接受 → 改取方案 B……2.2.10 第 1 款……"},
  "trace": {"sessionId": "S-01b938ba3de8", "events": ["…5 条…"]},
  "response": "天窗 07:30—09:20，12 条作业，给出两套候选方案：…"
}
```

`conflictCount` 在 `NEGOTIATE` 里是**建议方案**的冲突数（A 顺延为 0），
不是原窗口的 10 条 —— 演示时别说岔。

## 五、五个坑（真实错误码 → 真因 → 解法）

| # | 报错 | 真因 | 解法 |
|---|---|---|---|
| 1 | `AgentArts.03008001 runtime service is not activated` | 授权页有服务未授权（AI Defender） | 补授权 + 引用授权按钮「一键开通及授权」 |
| 2 | `SVCSTG.SWR.4030170 Insufficient permissions` + `failed to get image pull/push credential` | 运行时拉私有镜像拿不到凭据（子账号权限） | **SWR 仓库改公开** |
| 3 | `NA.20001 no match for platform in manifest` | 镜像索引标成 amd64 | `buildx build --platform linux/arm64` |
| 4 | `Timeout waiting for registration` | SDK 0.1.10 **没有** `@app.invocation_handler`，照着官方文档写会启动即崩 | 用 `@app.entrypoint` + **同步函数返回 dict** |
| 5 | `callback_addresses is empty` | ① 用异步生成器（流式）会要回调地址；② 运行时更新后首次调用也会偶发 | 用同步函数；偶发时**重试一次**即可 |

### 关于坑 4、5 的说明

官方文档示例写的是：

```python
@app.invocation_handler
def handle_invocation(request: dict) -> dict:
```

但 SDK 实测只有 `entrypoint`：

```
公开成员: ['add_exception_handler', 'add_middleware', 'add_route', 'async_task',
          'entrypoint', 'force_ping_status', 'ping', 'run', ...]
```

所以正确写法是：

```python
@app.entrypoint
def handle_invocation(request: dict) -> dict:
    return {"response": "...", "status": "ok"}
```

**同步函数 + 返回 dict**：既不流式（不触发回调要求），也能正常注册。

## 七、重新部署的完整流程

```powershell
# 设环境（见第二节）
cd "C:\Users\21264\ds harness work\work\contest-entry\agentarts"

# 1. 重建镜像
& $docker buildx build --platform linux/arm64 --provenance=false --sbom=false `
    -t "swr.cn-southwest-2.myhuaweicloud.com/skylight/skylight-check:latest" --push .

# 2. 删旧运行时（必须，否则沿用 Error 状态）—— 三个运行时共用一个镜像，要一起重建
foreach ($a in @("skylight-check","skylight-orchestrator","skylight-arbiter")) {
    agentarts destroy --agent $a --yes
}
Start-Sleep -Seconds 70      # 删除是异步的，太早会报 "Runtime is being deleted"

# 3. 创建新运行时（镜像已推，务必加 --skip-build，否则会用经典 docker build 产出 amd64）
foreach ($a in @("skylight-check","skylight-orchestrator","skylight-arbiter")) {
    agentarts launch --agent $a --skip-build
}

# 4. 验证
python invoke_agent.py full       # CHECK 应仍为 10 条
python invoke_agent.py negotiate  # 单运行时全链路，建议 A
python negotiate_cloud.py         # 三运行时协同
```

> `--skip-build` 是**开关，不带值**。写成 `--skip-build true` 会报
> `Got unexpected extra argument(s) (true)`。

## 九、三个运行时（方案三）

同一个镜像部署三次，靠环境变量 `AGENT_DEFAULT_MODE` 区分默认角色 —— 不传 `mode` 就是该角色。
配置由 `_add_agents.py` 从 `skylight-check` 复制生成（幂等，可重复跑）。

```powershell
python _add_agents.py                       # 写入 orchestrator / arbiter 两个配置块

$agents = @("skylight-check","skylight-orchestrator","skylight-arbiter")
foreach ($a in $agents) { agentarts destroy --agent $a --yes }
Start-Sleep -Seconds 70
foreach ($a in $agents) { agentarts launch --agent $a --skip-build }
```


### 坑 6：跨运行时的中间产物会「缺字段」

仲裁者拿到的 `checks` 是核查者回包的**精简版**（只有 `planId / conflictCount / severe`，
没有 `conflicts` 明细）。如果代码里直接 `c["conflicts"]`，云端返回
`status=500, {'error': 'KeyError', 'message': "'conflicts'"}`。

**判据**：跨运行时的契约要把字段分成「必须」和「可选」两档，读可选字段一律 `.get()`。
同一个函数被「本地全链路」和「跨运行时」两种方式调用时，最容易漏这一条。

> 顺带一个部署事实：三个运行时共用一个镜像 tag，**改代码必须三个一起重建**，
> 否则会出现「编排者是新版、仲裁者是旧版」的混合状态。
